## 5. 并行策略

### 可并行主线

1. 语义与 Planner
2. 查询与指标包
3. 解释模板与结果结构
4. 前端模板化结果页
5. 学习闭环与评测
6. 部署与运维

### 必须串行的关键点

1. `query_plan` 契约字段确定后，前端和解释层才能稳定消费。
2. `metric_bundle` 和 `report_template` 命名固定后，查询层与前端才能一起配置化。
3. Learning/Harness 的自动扩样必须建立在稳定的语义/SQL 回归链路之上。
4. 外部对标 Provider 必须在内部口径稳定后再接入，否则容易把错误归因到外部数据。

## 6. 无人值守模式规则

无人值守模式下按以下原则执行：

1. 优先推进已确认的阶段目标，不随意切换方向。
2. 每轮开发后必须补：
   - 代码
   - 测试
   - 文档
3. 每轮优先确保主链路可回归，不允许“看起来更高级，但主功能不稳定”。
4. 并行开发中每个 agent 负责独立写域，主线程负责合并、回归和收口。
5. 遇到高风险决策才暂停请求确认，例如：
   - 改数据库结构
   - 新增外部付费依赖
   - 涉及权限、安全、审计策略的不可逆改动
