# 项目迭代计划

更新时间：2026-04-17

执行状态：已获用户批准，进入无人值守 + 多 Agent 并行开发模式。总控计划见 [AUTONOMOUS_MULTI_AGENT_EXECUTION_PLAN.md](C:/Project/HotelAgent/hotel-ai-delivery-kit-v2/docs/02_ARCHITECTURE_EVOLUTION/AUTONOMOUS_MULTI_AGENT_EXECUTION_PLAN.md)。

## 1. 迭代目标

当前项目已经完成真实数据接入、移动端对话入口、基础语义解析、组合类报告输出和文档归档。下一阶段目标是把系统从“指标问答引擎”升级为“管理层经营分析编排器”。

核心转变：

```text
用户问题 -> 指标识别 -> SQL -> 单点解释
```

升级为：

```text
用户问题 -> 经营场景识别 -> 分析计划 -> 分组汇总 -> 分层分析 -> 管理层简报
```

## 2. 迭代原则

- 先解决管理层高频问题，再完善底层通用能力。
- 先用结构化 Planner 和确定性查询跑通，再引入大模型深度表达。
- 内部经营数据优先作为事实来源，外部行业对标作为可选增强。
- 每轮开发必须同步更新文档、测试和可验证样例。

## 3. 阶段计划

### P0：管理层集团经营汇总主链路

目标：让“公司所有酒店经营情况，请按管理公司和区域维度输出”这类问题真正按管理层汇报结构返回。

开发项：

- 识别 `管理公司`、`区域`、`管理公司 x 区域` 等分组输出指令。
- 在 `query_plan` 中新增 `group_by_dimensions`。
- 查询层新增按维度分组汇总结果。
- 解释层输出“总体概况、管理公司对比、区域对比、重点观察”。
- 前端优先展示分组汇总卡片，酒店异常放到后半段。

验收样例：

```text
请分析一下公司所有酒店3月份的经营情况，请汇总到管理公司和区域维度输出
```

期望：

- 识别为公司全集。
- 样本数显示公司全部酒店。
- 输出管理公司维度、区域维度、管理公司 x 区域维度。
- 指标至少包含总收入、经营利润（GOP）、ADR、OCC、RevPAR。

### P1：报告模板和指标包

目标：把业务 PPT 中的固定汇报结构沉淀为可维护配置。

开发项：

- 新增 `report_templates.yaml`。
- 新增 `metric_bundles.yaml`。
- 定义公司总览、管理公司区域、品牌对比、区域总览、单店分析、异常榜单模板。
- 将“经营情况”默认绑定到经营指标包，而不是单一指标。

### P2：Planner + Semantic Graph 主导链路

目标：让复杂问题由 Planner 先规划，再查数和表达。

开发项：

- 新增 Planner 合同字段：问题类型、分组维度、指标包、执行顺序。
- 强化 Semantic Graph：管理公司、品牌、子品牌、区域、资产包、科目层级。
- Skill 从主路由降级为辅助能力。
- 建立复杂问题 eval case。

### P3：Analysis Agent + Narrative Agent

目标：提升专业分析质量和管理层表达质量。

开发项：

- Analysis Agent 输出结构化经营观察。
- Narrative Agent 只负责表达，不越权补事实。
- 增加报告式回答的风格约束和模板。
- 保持首屏快路径，深度分析可异步补齐。

### P4：Learning Agent + 外部行业对标

目标：形成可控自学习闭环和可选行业对标。

开发项：

- 失败问题、用户纠正、二次追问进入 Learning Inbox。
- 自动生成 alias、planner pattern、eval proposal。
- 外部行业对标 Provider 接入，标注来源和时效。
- 建立人工审核后发布机制。
