# 语义维度识别层说明

## 1. 当前问题

此前语义解析主要识别酒店、区域、月份、指标，对管理公司、品牌、子品牌、建设来源、品牌档次、城市等级、部门、科目层级的利用不足。结果是用户问“万达管理的嘉华品牌”“餐饮部酒水成本”时，即使数据库里有字段，也没有被稳定转成查询条件。

## 2. 当前已接入的维度

### 经营驾驶舱宽表

来源表：

- `wddm_dim_overview_cockpit_f`
- `dim_allhotel_slcp`

已识别并可过滤：

- `requested_areas`：区域，例如华南区、海南区。
- `requested_hotels`：酒店，例如江门嘉华、广州丽思卡尔顿酒店。
- `requested_manage_corps`：管理公司/管理类别，例如万达品牌、国际品牌。
- `requested_brand_children`：品牌/子品牌，例如嘉华、万豪、希尔顿。
- `requested_builders`：建设来源，例如自建、原万达。
- `requested_brand_levels`：品牌档次，例如奢华级、标准五星级。
- `requested_city_levels`：城市等级，例如一线城市、新一线城市、二线城市。

### P&L 明细视图

来源视图：

- `vw_pnl_fact`

已识别并可过滤：

- `requested_departments`：部门，例如客房部、餐饮部、管理部门、固定成本。
- `requested_accounts`：科目/科目上级，例如收入、成本、利润、酒水成本、营业毛利、经营净利润。
- 同时继续支持酒店、区域、品牌、管理类别、建设来源过滤。

## 3. 查询链路

1. `semantic-service` 先从基础实体目录和内置维度词表识别业务维度。
2. 识别结果写入 `parsed_intent`。
3. `ai-query-service` 根据 `parsed_intent` 构造 SQL WHERE 条件。
4. `db-executor-service` 优先查询本地 DuckDB 分析缓存。
5. 回答结果保留 `parsed_intent` 和 `performance`，便于观察识别是否正确。

## 4. 已验证样例

### 区域 + 管理公司 + 品牌

问题：

```text
看华南区万达管理嘉华品牌3月经营情况
```

识别结果：

- 区域：华南区
- 管理公司：万达品牌
- 品牌/子品牌：嘉华
- 时间：202603

实测命中本地分析缓存，约 0.35 秒返回。

### 酒店 + 部门 + 科目

问题：

```text
解释江门嘉华3月餐饮部酒水成本为什么偏高
```

识别结果：

- 酒店：江门嘉华
- 部门：餐饮部
- 科目：成本、酒水成本
- 时间：202603
- 意图：explain

实测命中本地分析缓存，约 0.36 秒返回。

## 5. 后续增强方向

- 内部对标已支持分层回退：
  - 同区域同品牌同档次同城市等级
  - 同区域同品牌同档次
  - 同区域同品牌
  - 同区域
- 外部行业对标建议保留为用户显式开关，默认关闭。开启后表示用户接受后续联网抓取行业样本，但其准确性和时效性需人工评估。
- 从 `vw_pnl_fact` 自动生成完整科目树，包括 `account_nameF01`、`account_nameF02`、`account_name`、`accountName`、`account`。
- 将管理公司、品牌、子品牌、区域、酒店之间的从属关系生成一张维度图谱，避免用户输入冲突时查出空结果。
- 给前端增加“系统理解为”维度卡，展示管理公司、品牌、子品牌、科目层级，而不仅是酒店和时间。
- 将低命中、空结果样本写入学习收件箱，由 Harness 定期沉淀别名和新实体。
