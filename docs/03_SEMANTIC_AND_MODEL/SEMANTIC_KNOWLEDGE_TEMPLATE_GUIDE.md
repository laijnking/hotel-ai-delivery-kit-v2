# 语义知识模板填写说明

## 1. 用途

本目录用于收集让语义路由、小模型预解析和多轮对话更稳定所需的业务知识。

建议把可结构化的数据优先填写到 `templates/semantic_knowledge/` 目录下的模板文件中，再逐步接入系统。

## 2. 推荐填写顺序

优先级最高的四份：

1. `hotel_master.csv`
2. `metric_dictionary.csv`
3. `dialog_samples.csv`
4. `business_rules.md`

如果时间有限，先补这四份就能显著提升：

- 酒店、区域、品牌、管理方识别
- 指标映射
- 常见问法理解
- 默认口径和分析模式判断

## 3. 文件说明

### 3.1 `hotel_master.csv`

作用：

- 统一酒店主数据
- 支撑酒店、区域、品牌、管理方、城市等级等维度归一
- 为冲突检测和组合过滤提供基础关系

### 3.2 `metric_dictionary.csv`

作用：

- 定义指标中文含义和常见问法
- 明确默认口径和适用范围
- 支撑小模型语义提示词和后端归一化

### 3.3 `dialog_samples.csv`

作用：

- 给出真实或接近真实的用户问法
- 用于训练提示词、评测和回归
- 帮助系统识别意图、范围、口径和分析模式

### 3.4 `business_rules.md`

作用：

- 记录难以直接结构化的业务口径规则
- 定义哪些问法默认属于同比、预算、摘要、归因等

### 3.5 `entity_aliases.csv`

作用：

- 收集简称、别名、错别字和口语表达
- 用于实体识别和纠偏

### 3.6 `relation_rules.csv`

作用：

- 定义实体之间的合法从属关系和冲突关系
- 支撑“先澄清，不查空”的路由策略

### 3.7 `management_templates.csv`

作用：

- 定义管理层常见分析诉求
- 约束输出章节和推荐指标

### 3.8 `conversation_inheritance.csv`

作用：

- 定义多轮追问里的继承逻辑
- 例如“换成同比”“只看华南区”“继续展开原因”该继承哪些字段

### 3.9 `hard_cases.csv`

作用：

- 收集高歧义、易错和失败样本
- 用于后续专项回归

### 3.10 `department_dictionary.csv`

作用：

- 沉淀 P&L 部门层级问法
- 支撑“客房部”“餐饮部”“管理部门”等部门语义识别
- 为小模型追问和后端口径归一提供部门候选

### 3.11 `account_dictionary.csv`

作用：

- 沉淀 P&L 科目、一级科目、二级科目语义
- 支撑“酒水成本”“营业成本”“薪资及福利”等科目识别
- 为科目别名补充和 subject hierarchy 分析提供基础字典

## 4. 填写原则

- 一行只表达一个稳定事实。
- 优先填真实业务口径，不要写“可能”“大概”。
- 别名和错别字单独列，不要混进主名称。
- 如果一个字段暂时没有值，先留空，不要编造。
- 如果同一问题存在多个可能解释，优先写入 `hard_cases.csv`。

## 5. 建议放置位置

模板目录：

- `templates/semantic_knowledge/`

后续你补充后的真实数据，也可以继续放在这个目录，或者放到仓库外统一资料目录，再由系统读取。
